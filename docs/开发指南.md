# 开发指南

## 代码放在哪里

- 仅展示数据的 Compose 代码：对应 `feature` 的 `ui` 包；超过约 80～120 行时按 Section 拆分。
- 页面状态、用户事件、一次性动作：分别定义为 `UiState`、`Event`、`Effect`。
- 页面状态变换和生命周期协程：ViewModel。
- 可复用或有业务含义的规则：`core:domain` 用例。
- Repository 契约和业务规则：`core:domain`；数据读取与同步实现：`core:data`。
- HTTP/序列化：`core:network`；Room/文件/偏好：`core:database`。
- 颜色、字号、间距、跨业务 UI：`core:designsystem`。
- 具体依赖装配与顶层路由：`app`。

## 强制边界

1. Composable 不调用 Repository、DAO、网络客户端或 UseCase。
2. Screen 参数只包含稳定的 State、展示模型和事件回调；生命周期收集放在 Route。
3. Feature 不持有 `NavController`，也不引用其他 Feature 的 Screen。
4. `MutableStateFlow` 只在 ViewModel 内部暴露，外部只能读取 `StateFlow`。
5. UiState 是不可变 `data class`，同一页面不得再维护平行的 loading/error/list 真相源。
6. Feature 禁止写品牌色和跨页面组件；先沉淀 Design System token 或组件。

## 数据流模板

```text
用户操作
  -> Screen 发送 Event
  -> ViewModel 处理 Event
  -> UseCase 执行业务规则
  -> Repository 协调 Network / Database
  -> StateFlow 发布唯一 UiState
  -> Route 生命周期安全地收集
  -> Screen 根据 State 重组
```

导航等一次性动作走 `Effect -> Route -> Navigator -> app`，不塞进可重放 UiState。

## 替换示例基础设施

- 网络：实现 `ArticleRemoteDataSource`，在 `AppContainer` 将 `FakeArticleRemoteDataSource` 换成真实实现。
- 数据库：实现 `ArticleLocalDataSource`，将 `InMemoryArticleLocalDataSource` 换成 Room 实现。
- 依赖注入：保留构造器注入，把 `AppContainer` 的绑定迁移到 Hilt/Koin 模块。
- 导航：保留 Feature 的 Navigator 接口，把 `EnterpriseApp` 的轻量回退栈替换成 Navigation Compose。

这些替换都不要求修改纯 Screen，也不改变单向数据流。

## 提交前检查

```bash
./gradlew test
./gradlew :app:assembleDebug
```

同时检查：新增页面是否有 Preview、State 是否唯一、事件是否统一、Feature 是否越层依赖、组件是否应沉淀到 Design System。
